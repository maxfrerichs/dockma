tl;dr

dockma boots a minimal Linux VM with Apple's Virtualization.framework and runs a stripped-down Linux distribution with Docker Engine inside it. The macOS docker CLI communicates to the engine through a Unix socket. A launchd job keeps it running in the background.

Docker on a Mac, without the hassle.

dockma is a Docker runtime for Apple Silicon Macs, an alternative to running the engine through Docker Desktop, Colima or OrbStack. You keep using the docker CLI on your host; dockma only provides the engine behind it.

It is currently in early development : Apple Silicon only, and tested on macOS 27 so far. See the known limitations before relying on it.

Feel free to install, daily-drive and report issues, but if you need a battle-tested, production-ready alternative, consider Colima.

Quick start

Install a release

{{ partial "commands.html" hugo.Data.install }}

Needs an Apple Silicon Mac with macOS 14 or later and the docker CLI (brew install docker). The script checks the download against the release's SHA256SUMS (and its build attestation, if gh is logged in), installs dockma to ~/.local/bin and fetches the matching Linux guest. Set DOCKMA_VERSION to pin a release or DOCKMA_INSTALL_DIR to install elsewhere. Optional: Rosetta for amd64 images. If DOCKER_HOST is set (Lima does this), it overrides the context.

How it works

macOS
dockerdockmalocalhost:P
▼
dockma daemon launchd job · owns the VM
vsock
Linux guest dockma-agent ▼
dockerddocker-proxy/bin/sh

virtiofs: $HOME, Rosetta · virtio-blk: /var/lib/docker

A lightweight daemon owns the VM and pipes the Docker, shell and port connections to a Go agent in the guest over vsock. The guest image is built reproducibly from one Dockerfile with pinned versions; the kernel and Docker downloads are sha256-checked.
