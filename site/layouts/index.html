Docker on a Mac, without the hassle.

dockma is a Docker runtime for Apple Silicon Macs, an alternative to running the engine through Docker Desktop, Colima or OrbStack. It boots a minimal Linux VM with Apple's Virtualization.framework and runs Docker Engine inside it. You keep using the docker CLI on your host: it talks to the engine through a Unix socket, and a launchd job keeps the VM running in the background.

It is in early development. Feel free to install it, daily-drive it and report issues, and read the known limitations first. If you need a battle-tested, production-ready alternative, consider Colima.

A VM built for one job

The guest is not a general-purpose distribution. Everything in it exists to run Docker, and all of it is built from one Dockerfile.

  • Kernel: Linux {{ $facts.kernel }}, configured from tinyconfig with only what Docker needs. Everything is built in, with no modules.
  • Userspace: a busybox initramfs with Docker {{ $facts.docker }}'s static binaries. Its init keeps two services running: dockma-agent, a Go service on vsock, and dockerd.
  • Stateless root: the root filesystem is rebuilt on every boot. Only /var/lib/docker lives on the data disk.
  • Verifiable: kernel and Docker downloads are pinned and sha256-checked. Release builds carry provenance attestations.

Quick start

Install a release

{{ partial "commands.html" hugo.Data.install }}

Needs an Apple Silicon Mac with macOS 14 or later and the docker CLI (brew install docker). The script checks the download against the release's SHA256SUMS (and its build attestation, if gh is logged in), installs dockma to ~/.local/bin and fetches the matching Linux guest. Set DOCKMA_VERSION to pin a release or DOCKMA_INSTALL_DIR to install elsewhere. Optional: Rosetta for amd64 images. If DOCKER_HOST is set (Lima does this), it overrides the context.
